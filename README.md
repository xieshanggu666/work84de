# 📋 招聘流程管理与人才智能匹配平台（TalentFlow）

面向 HR 的一站式招聘流程管理系统：管理职位发布、候选人投递、简历解析、**人岗智能匹配评分**、面试安排、Offer 发放与入职驱动。平台以职位与候选人建档为基础，通过技能权重/年限/薪资/学历等多维加权计算匹配度，自动推荐高匹配候选人，并驱动简历筛选、面试评价与招聘漏斗分析。关键动作（候选人推进、面试结论、Offer 发放）纳入**角色权限 + 可退回审批链**，审批通过后自动回写招聘阶段与 Offer 状态，全程审计通知。

## 技术栈

- **前端**：Vue 3 + Vite + Pinia（状态管理）+ 内联 SVG 图表
- **后端**：Express + Node.js 内置 `node:sqlite`（需 **Node ≥ 22.5**）
- **数据库**：SQLite（`server/hr.db`）
- **通信**：REST API，Vite 代理 `/api` 到后端
- **启动**：`concurrently` 同时拉起前后端

## 数据模型（SQLite 表）

| 表 | 说明 |
|----|------|
| `positions` | 职位（技能权重 `skills` JSON、薪资带宽、编制） |
| `candidates` | 候选人（结构化技能、年限、学历、期望薪资、来源渠道） |
| `matches` | 人岗匹配**最新结果**（总分 + 各维度得分 + 理由 + 短板 + `computed_at` + `strategy_id`，随重算更新） |
| `match_strategies` | 每个职位发布的匹配策略（五维权重 + 关键词加分上限；无记录=系统默认） |
| `strategy_versions` | 策略发布留痕（每次发布一个版本，匹配记录按版本号追溯评分依据） |
| `recalc_jobs` | 显式重算批次（策略发布、手动批量重算、启动迁移），串联策略版本和重算范围 |
| `recalc_items` | 批次内每个职位×候选人的评分明细，作为 `matches` 最新分的审计证据 |
| `applications` | 应聘记录（Stage 状态机 + `match_snapshot`/`matched_at` 投递时评分快照 + `stage_snapshot`/`entered_at` 当前阶段快照 + `reject_from` 淘汰来源 + `version` 乐观锁） |
| `application_events` | 候选人每次进入/退出阶段的不可变事件，固化当时评分、策略版本和重算批次；每个 应聘×阶段 仅一条最新正式事件，回退/复活刷新该行 |
| `offer_change_logs` | Offer 变更留痕（发起/调薪/改期/接受/拒绝/入职/撤回），只追加不改写 |
| `interviews` | 面试轮次、评价与**面试结论**（`conclusion`：待定/通过/不通过，结论驱动阶段联动） |
| `offers` | Offer 与接受/入职流转（含撤回、决定人/时间、入职时间） |
| `channels` | 招聘渠道及成本 |
| `users` | 平台用户与角色（`recruiter` 招聘负责人 / `interviewer` 面试官 / `hiring_manager` 用人经理） |
| `approval_tasks` | 审批任务（类型、申请内容快照 `payload`、提交时固化的审批链 `chain` 与 `current_step` 指针、状态、`version` 乐观锁） |
| `approval_steps` | 审批步骤留痕（提交/逐级通过/退回/重提/撤销/执行回写，只追加不改写） |
| `notifications` | 审计通知（按接收角色投递：待审提醒/退回/生效/失败/撤销，可标记已读） |

## 角色权限与审批链

平台内置三类角色（顶栏可切换身份，每次请求携带 `x-user-id` 由服务端强制校验）：

| 角色 | 权限 |
|------|------|
| 🧭 招聘负责人 | 提请**候选人推进**、发起 **Offer 发放**申请；审批**面试结论**；超带宽 Offer 终审；淘汰/回退/安排面试/Offer 日常管理 |
| 💬 面试官 | 提交**面试结论**（通过/不通过）申请；填写面试评价 |
| 🏢 用人经理 | 审批**候选人推进**与 **Offer 发放**申请 |

- **三类审批任务**：候选人推进（招聘负责人 → 用人经理）、面试结论（面试官 → 招聘负责人）、Offer 发放（招聘负责人 → 用人经理）；**Offer 月薪超职位带宽上限时自动加签**招聘负责人终审，形成两级链。
- **可退回**：审批人可「退回」并必填意见，任务回到申请人；申请人修改内容后**重新提交**，审批链按新内容重建（如薪资降回带宽内则取消加签）并从第一级重审；进行中/已退回的任务可撤销。
- **结果回写**：终审通过在**同一事务**内调用与直接操作完全相同的业务函数（推进状态机 / 结论联动 / Offer 发起），回写招聘阶段、面试结论与 Offer 状态；执行时若业务状态已漂移（如阶段被其他操作变更），仅回滚执行段（SAVEPOINT），任务标记「执行失败」并通知申请人，审批留痕保留。
- **防重复**：同一应聘同一类型仅允许一个进行中的审批；任务带 `version` 乐观锁防并发审批；越权操作返回 403 并提示所需角色。
- **审计通知**：提交/逐级通过/退回/重提/撤销/生效/失败均写入 `approval_steps` 并按角色投递 `notifications`；顶栏铃铛查看未读，审批中心「全部记录」可审计每个任务的完整步骤时间线。

## 匹配策略、批量重算与历史评分

- **按职位配置并发布策略**：职位卡片「⚙️ 匹配策略」中调整技能/年限/薪资/学历/城市五维权重（滑块百分比，发布时自动归一化为 100%）与简历关键词加分上限，可一键恢复默认；发布即留痕版本并立即重算该职位全部推荐。
- **批量重算**：智能匹配页「🔁 按策略批量重算全部推荐」按各职位当前策略刷新所有在招职位×候选人的最新结果；接口也支持只重算单个职位。每次显式重算都会生成 `recalc_jobs` 批次，并在 `recalc_items` 中保存每组职位×候选人的评分明细。浏览推荐列表只实时展示，不会隐式改写“最新结果”。
- **投递快照 → 阶段快照 → 最新结果的可追溯链路**：候选人投递瞬间固化 `applications.match_snapshot`；每次推进到筛选/面试/Offer/录用以及淘汰/Offer 拒绝，都会在 `application_events` 写入不可变阶段事件，保存当时分数、维度、理由、短板、策略版本和重算批次。之后任何重算只更新 `matches` 与 `recalc_items`，投递和阶段快照不变。
  - **招聘流程看板**：卡片按「投递评分 → 进入当前阶段评分 → 最新重算」并列展示，可在三种口径间切换；点击「🔗 追溯」可查看候选人完整阶段时间线。
  - **按策略版本回看**：看板和追溯抽屉可选择 `v0 默认策略` 或任一已发布版本，查看候选人进入各阶段时使用的权重、关键词上限、维度分、理由、短板及对应重算批次。
  - **重算/推进一致性**：策略发布+批量重算、投递+投递事件、阶段推进+阶段事件、Offer 接受/拒绝+终态事件均在同一个 SQLite 事务中提交；流程推进只读取并固化当前最新分，不触发重算，避免重算覆盖阶段决策依据。
  - **报表中心**：匹配度分布环形图支持在「投递时评分 / 最新结果」两种口径间切换，并对比两个口径的平均分。
- **兼容已有数据**：启动时自动为旧库补表，将历史匹配归入一次 `startup` 重算批次，并为升级前产生的投递记录回填投递快照和当前阶段事件（均标记「补录」）。

## 招聘流程状态协同

投递→筛选→面试→Offer→录用/入职的每次状态变更都由服务端统一的状态机驱动，并在**同一 SQLite 事务**内完成「应用阶段 + 乐观锁版本 + 阶段快照 + 阶段事件 + Offer 留痕」的同步，保证看板、面试、Offer、追溯、报表五处口径一致：

- **阶段推进约束**：只能沿顺序前进；进入 Offer 前最近一轮面试结论必须为「通过」（无面试/待定/不通过均拦截并提示）；Offer→录用只能由「接受 Offer」驱动，不能跳过候选人确认。
- **面试结论协同**：最近一轮结论置「不通过」自动淘汰（记录淘汰来源 `reject_from`）；淘汰态下改判「通过/待定」可复活回面试阶段。录用后结论锁定，重复提交同一结论按幂等处理。
- **Offer 变更约束**：仅允许 待回应→接受/拒绝/撤回、已接受→入职/撤回；接受后或终态下禁止改薪（仅待回应可调薪/改期），每次变更追加 `offer_change_logs`。候选人拒绝 Offer 自动淘汰；撤回进行中 Offer、或从录用异常回退时，Offer 同步撤回。被撤回/拒绝的 Offer 可在原记录上重新发起（保留历史）。
- **异常回退**：每个阶段可回退到上一阶段（录用→Offer→面试→筛选→投递），写 `rollback` 事件并以当前最新分刷新该阶段快照；淘汰记录按 `reject_from` 复活。投递阶段不可再退。
- **重复操作保护**：`applications.version` 乐观锁——前端携带读取时的版本，重复点击/并发/过期页面提交返回 409 `version_conflict` 并自动刷新；同键操作在前端串行化（按钮置灰），服务端对重复投递、重复发起待回应 Offer、终态操作、非法状态跳跃一律 4xx 拒绝。
- **三快照口径**：投递快照（永不改变）、当前阶段快照（随推进/回退/复活刷新）、最新重算（仅显式重算更新）。看板评分切换、追溯时间线、报表分布/漏斗共用同一数据源；漏斗支持「当前阶段 / 曾经到达（按事件去重）」两种口径。

## 人岗匹配评分算法

按职位匹配候人或按候选人推荐职位时，综合五维加权（权重可由 HR 按职位覆盖，默认技能 40% / 年限 20% / 薪资 15% / 学历 15% / 城市 10%）：

- **技能**（权重 40%）：候选者命中职位要求的技能及其熟练度
- **经验年限**（20%）：与职位所需年限对比
- **薪资匹配**（15%）：期望薪资落入职位带宽程度
- **学历**（15%）：博士/硕士/本科/大专
- **城市地点**（10%）+ 简历关键词加分

输出 0-100 总分与各维度得分条，并给出推荐理由与短板提示（如"关键技能覆盖不足"、"期望薪资超带宽"）。

## 核心流程

智能匹配 → 纳入招聘流程 → 提请推进审批（逐级审批后回写阶段）→ 面试结论审批（生效后联动推进或淘汰）→ Offer 发放审批（超带宽加签终审）→ 候选人接受 → 入职；审批可退回重提，支持淘汰复活与异常回退，所有状态实时落库并全程审计通知。
